## D. Claude分析：お金と提出物の設計案（2026-09-11・未合意）

### D-1 現状のお金は「2つの別モデル」が並存している
| | 大会側（コンテスト行の列） | おでかけ側（別シート） |
|---|---|---|
| 考え方 | **集金モデル**＝藤本さんが主催者へ払い、各家庭から集める前提。列が家族×項目で固定（`Airi_エントリー費_支払済` 等） | **台帳モデル**＝記録ごとに「支払者」「負担者（乗車メンバー／その他費用のtargets）」を持ち、収支ネットから送金を自動算出。回収ステータス付き |
| 持てる費目 | エントリー費・観覧費・交通費（ガソリン/ETC）・その他1件 | 高速・ガソリン（距離×燃費で計算）・駐車場・その他費用（複数、人別対象） |
| 「1人が全員分の食事代を立替」 | 表現できない（その他1件のみ・支払者概念なし） | 表現できる（その他費用＋targets） |
| 「2家族だけ乗り合わせ」 | 交通費_対象フラグで一応可 | 乗車メンバーで可 |
| 交通費 | **両方にある＝二重** | |

→ 煩雑さの正体は「同じ交通費・立替が2か所にあり、精算の単位も別（大会ごと／プロジェクトごと）」なこと。

### D-2 提案：概念を2層に分ける
**層1「やること」（主催者に対する提出・支払い）**＝タスク。精算とは無関係。
- 4項目：要否／いつまで（日付 or「当日」）／状況（未・済）／メモ
- 「当日」を期限の一種として扱えば、事前と当日が同じ1行になる。当日のものは自動で「当日の持ち物」に集まる
- 音源 a) ＝「音源提出（事前・期限日）」＋「予備CD持参（当日）」の2行、b) ＝「CD持参（当日）」＋「予備データ準備（当日）」の2行
- エントリー費が当日払い＝「エントリー費 ¥3,000 持参（当日）」の1行。事前振込＝「エントリー費 振込（期限日）」の1行
- 自動ステータス（準備中→当日待ち→完了）はこの層だけで計算できる

**層2「お金」（家族間の立替と精算）**＝台帳。おでかけ側の考え方に統一する。
- 1行＝日付／金額／内容／支払者（誰の財布から出たか）／負担者（誰の分か・複数可）／紐づく大会（任意）／精算済
- エントリー費・観覧費・高速・ガソリン・駐車場・食事・その他、すべて同じ1行。高速料金計算やETC割引・観覧費の人数計算は「金額を出す入力ヘルパー」に降格し、保存されるのは1行の金額
- 層1で「エントリー費 振込 済」にした瞬間に「誰が払った？→精算に載せる／載せない」を聞いて層2へ1行足す（藤本さんが3家庭分まとめて振込むケースを1タップで記録）
- 精算は「負担−支払」のネットから送金を出す今のロジックをそのまま流用
